# 外部題目

其他評測的題目都是開發時自己寫的，規則也照著它們調過，分數難免偏高。這個資料夾收的是**別人出的題**：出題的人沒看過現有題庫，題目也不拿來調整系統，只用來量。

## 出題說明（可以直接轉傳）

> 我做了一個宜蘭、花蓮、臺東避難所的問答系統，想請你幫忙出 5～10 個問題，測它答得好不好。
>
> - 想像你住在東部、遇到地震、颱風、淹水或土石流，會想問什麼，就照你平常打字的方式寫，不用刻意寫得很正式。
> - 可以問：某個地方附近有哪些避難所、某間避難所的容量或設施（例如有沒有無障礙設施、能不能帶寵物）、防災知識（警戒是什麼意思、要準備什麼）。
> - 也歡迎問它**不該**回答的：其他縣市、跟避難無關的事、資料裡沒有的東西。系統應該拒答或說查不到。
> - 「期待的回答」可填可不填：寫下你覺得好的回答應該包含什麼（例如「應該列出七星潭附近的避難所」「應該說查不到」）。
> - 請不要先去試用系統或看專案裡的例子，出完再玩。
>
> 填在附的表格（`questions_template.csv`，Excel 可開），或直接傳文字給我也可以。

## 收題之後

1. 把題目整理成 `questions.csv`（欄位同 `questions_template.csv`；`id` 可以留空，`出題者` 填代號就好，例如 A、B、C）。
2. 讓系統回答，寫出待評的表：

   ```bash
   docker exec disaster_app python evals/run_heldout_eval.py answer evals/datasets/heldout/questions.csv
   ```

3. 打開 `evals/results/heldout_answers.csv`，逐題在「判定」欄填下面其中一個，有疑問的寫在「備註」：

   | 判定 | 什麼時候用 |
   |---|---|
   | 正確 | 回答了問題，內容跟資料相符，沒有編造 |
   | 部分正確 | 方向對，但漏了重要的避難所或資訊，或多了不相干的 |
   | 錯誤 | 答錯、答非所問、編造資料庫裡沒有的避難所或數字 |
   | 正確拒答 | 題目超出範圍（其他縣市、無關、資料沒有），系統也說答不了 |
   | 不該拒答 | 資料裡答得出來，系統卻說答不了 |

   判定時對照資料本身（地圖上的避難所資訊、`data_for_refuge/`），不要只看回答讀起來順不順。能的話請出題的人判定自己的題，或兩個人各判一次、對不一致的題目討論，避免自己出系統、自己給分。

4. 計分：

   ```bash
   docker exec disaster_app python evals/run_heldout_eval.py score
   ```

   以「正確 + 正確拒答」算答對，附 95% bootstrap 信賴區間，並依路由、程式組的回答與模型生成分開算。結果存在 `evals/results/heldout_eval.json`。

題目是在沒有模擬進行時問的；模擬追問由 `evals/run_simulation_eval.py` 另外量。
